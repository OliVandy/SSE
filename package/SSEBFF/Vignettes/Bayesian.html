Sample Size Estimation for Clinical Trials in Multiple Paradigms-Bayesian

Rachel Zhuang and R. Oliver VandenBerg

2025-07-01

The SSEBFF package is designed to assist in sample size estimation for clinical trials across various paradigms, including Frequentist and Bayesian. This vignette focuses on the Bayesian paradigm.

Introduction

Sample size estimation is a critical step in the design of clinical trials. The SSEBFF package provides tools for estimating sample sizes in Bayesian clinical trial designs.

In Bayesian paradigms, the sample size can be estimated using a Bayesian estimator that incorporates prior information and the desired posterior probability of success. The package allows users to specify the prior distribution, the effect size, and the desired level of statistical power.

One-arm trial means we are testing a single treatment against a null hypothesis. Two-arm trial means we are comparing two treatments, like a new drug against a control treatment.

The hypothesis testing framework used in Bayesian paradigms is different from frequentist approaches. In Bayesian analysis, we calculate the posterior probability of the hypothesis given the data and prior information. The posterior probability is the probability of the alternative hypothesis being true after observing the data, which is a key difference from the frequentist approach that relies on p-values.

library(SSEBFF)

We will demonstrate the package function through example simulations. In this package we provide a combined function for sample size estimation for both one-arm and two-arm trials.

BESS_unified

Estimates the minimum required sample size to achieve a desired posterior probability threshold c based on Bayesian inference, supporting binary and continuous outcomes for one-sample designs, and binary outcomes for two-sample designs. This is based on controlling the posterior probability xi to exceed a cutoff value c when the observed treatment effect exceeds a certain proportion e.

e is the assumed value of \(\theta\) under \(H_a\) used to simulate or compute the probability of detecting an effect. In other words, how strong you think the treatment will work before you actually run the study. You’re guessing: “If I give this new drug to people, I think maybe it’ll help about 60% of them.” you assume \(\theta\) = 0.6 when simulating data.

c is the threshold set for posterior probability. To be more specific, it is how sure we want to be (statistically) before we say the treatment works. Eg. c = 0.9 means you want to be at least 90% sure the treatment is better, or 90% sure that we will reject the null hypothesis.

For example, we want estimate the sample size needed to check if the proportion of left-handed people in a population is really 0.1. We assume that the true proportion of left-handed people is 20% (e = 0.2). We want to be at least 95% sure (c = 0.95) that our sample size is sufficient to detect this difference. In this case, the needed sample size is 20.

BESS_unified(theta0 = 0.1, c = 0.95, e = 0.2, type = "one.sample",
             outcome = 1, a = 1, b = 1, q = 0.5)

Post_Prob_Bayes: Posterior Probability

When we know the sample size, we could then use the Post_Prob_Bayes function to compute the posterior probability that a parameter exceeds a threshold using Bayesian updating for one-sample or two-sample scenarios. Supports binary and continuous outcomes for both one-arm and two-arm tests.

The threshold, also referred to as margin, is the value we want to compare against, like a benchmark or a minimum effect size. For example, in a one-arm trial, it is the null hypothesis value, which is the value we want to test against, $^* $.

Delta is the difference we want to detect between the treatment and control groups. In a two-arm trial, if we want to know if a new treatment is better than the current one by at least 10%, we set delta to 0.1. \(\theta_T - \theta_C\) > 0.1.

The prior is the initial belief about the parameter before seeing the data. It can be a Beta distribution for binary outcomes, a Normal distribution for continuous outcomes, or a Gamma distribution for count outcomes. The prior reflects our initial knowledge or assumptions about the parameter before we collect any data.

We want to check if the average height of American male population is greater than 178 cm. We assume the average height is 180 cm (e = 175) with a standard deviation of 4 cm (sig = 4). We want to be at least 95% sure (c = 0.95) that our sample size is sufficient to detect this difference. In this case, we can use the Post_Prob_Bayes function to compute the posterior probability.

Post_Prob_Bayes(type = "one.sample", n = 30, theta0 = 178, outcome = 2, e = 175, sig = 4, a = 170, b = 10)
## [1] 1.624469e-05

The probability that the true mean is greater than 178 is about 0.0016%. It’s extremely unlikely the true mean exceeds 178. We do not reject the null hypothesis.

BESS_SSR_Design

Because in real-world trials, uncertainty is high early on, and the original guess (the assumed effect size e) might be wrong, we need to restimate the sample size. This function performs a Bayesian Estimator of Sample Size (BESS) with interim analysis and optional sample size re-estimation for a binary, continuous, or count outcomes for both one-arm and two-arm clinical trial.

It starts with an interim analysis at a small sample size n0, then Decides whether to stop early for success or futility, or continue to the next stage. If continuing, re-estimates the sample size using Bayesian Expected Sample Size (BESS) methods based on observed interim data. Finally, it makes a decision after simulating the second-stage data.

In a medical trial, we want to start with a small sample size, say 30 patients, to see if the treatment is working. If it looks promising, we can then increase the sample size to get more data and make a better decision. In this case, n0 = 30.

c_s is the posterior probability threshold for early futility. If the posterior probability of success is less than or equal to c_s, we stop the trial and declare futility. In the other hand, if the posterior probability of success is greater than or equal to c, we stop the trial and declare success.

cap is when we want to set a maximum sample size for the trial. If cap = TRUE and the re-estimated sample size exceeds n_cap, we stop the trial and declare success.

For example, a hospital wants to evaluate whether a new sanitation protocol can reduce the average number of hospital-acquired infections (HAIs) in a particular ward. Historically, the ward sees about 5 infections per month (\(\theta_H\) = 5). The hospital’s goal is to bring this average down to 4 or fewer per month (\(\theta_s\) = 4). They use a Bayesian design to adaptively determine if the protocol is effective enough to recommend hospital-wide implementation.

We observe the number of infections over the first 60 days after implementing the new protocol. Then calculate the posterior probability that the true average infection rate is \(\le4\) using the data from the first 60 days.

If this probability is \(\ge0.95\), declare success and recommend the protocol. If it is \(\le0.1\), stop for futility. Otherwise, continue collecting data (possibly with an adaptively determined sample size). Then the design computes how many more days (or months) of observation are needed to reach a conclusive decision, using the observed data to update the Bayesian posterior.

BESS_SSR_Design(type = "one.sample", theta_H = 5,
                theta_s = 4, c = 0.95, c_s = 0.1, n0 = 60,
                outcome = 3)

Gamma-Poisson Model

The Gamma-Poisson model is a Bayesian approach for analyzing count data, particularly useful in clinical trials where the outcome is a count of events (e.g., number of adverse events). This model assumes that the counts follow a Poisson distribution with a gamma-distributed rate parameter. The posterior probability in this case is the count of the treatment group has a higher event rate than count control.

Count_Sample_Size

Computes the minimum sample size needed to achieve a posterior probability of superiority greater than or equal to a critical threshold, under a Gamma-Poisson model for count outcomes.

Say we want to estimate the sample size needed to check if the average number of success shots made by a basketball Player A is greater than Player B by at least 1 event. We assume that the average shots/game for Player A is 12 and the average shots/game for Player B is 8. We want to be at least 90% sure (crit = 0.9) that our sample size is sufficient to detect this difference. In this case, we can use the Count_Sample_Size function to compute the sample size.

Count_Sample_Size(type = "two.sample",

Count_Post_Prob

Computes the posterior probability that the treatment event rate exceeds the control rate by a threshold using Gamma priors and Poisson likelihoods.

FOr example, you are monitoring the rate of hospital-acquired infections per 10 patient-days in the ICU unit. Over the past 20 patient-days, you observed 45 infection events. Historically, an infection rate above 2.5 per 10 patient-days is considered unacceptably high. You want to compute the posterior probability that the current infection rate exceeds 2.5 — using a weak prior (Gamma(0.5, 0.5)) to stay conservative.

Count_Post_Prob(type = "one.sample", total_count = 45, sample_size = 20,
                threshold = 2.5, a_t = 0.5, b_t = 0.5)
## [1] 0.1928

We’re 19.59% sure the true infection rate exceeds 2.5 — it’s not a serious problem.

Two_Arm_Standard_SSE_Design

Simulates a two‑arm clinical trial with binary outcomes.
The design supports an optional interim look that applies a Bayesian error‑spending rule; otherwise, the final decision is based on a traditional frequentist z‑test against a non‑inferiority/superiority margin.

This design evaluates whether the treatment group performs significantly better than the control group, considering a pre-specified superiority margin (theta_s). The function supports early stopping for success or futility based on Bayesian posterior probabilities, followed by a final frequentist z-test if no early decision is made.

interim: Logical, if TRUE, perform an interim Bayesian analysis at sample size n_0. If posterior \(\le\) c: Stop early for success. If posterior \(\le\) c_s: Stop early for futility. Otherwise: Continue to enroll up to n_f, and perform the same frequentist z-test as above for final decision-making. If FALSE, perform a final analysis at sample size n_f. If the p-value \(< \alpha\), declares success. Otherwise, failure.

An online retailer has developed a new checkout process (H) and wants to compare it against their existing process (L). The outcome of interest is whether a user completes the purchase (success = 1, failure = 0). Since we are conducting a one-sided test, the significance level is set to 0.025 (half of the original \(\alpha\)). We observe the outcomes of interest over the first 50 users after implementing the new checkout process. If the new process is clearly superior/inferior, stop early. Otherwise, continue to collect data to 100 per group for a final decision.

Two_Arm_Standard_SSE_Design(
  n_f     = 100,
  theta_H = 0.65,
  theta_L = 0.50,
  theta_s = 0.10,
  alpha   = 0.025,
  interim = TRUE,
  n_0     = 50)
## [1]  0.66  0.56  0.00 50.00

In this case, the posterior probability of success is 0.74, which is less than the threshold of 0.975, so we stop early for futility. The decision indicator is 0, and number of subjects use is still 50.

Non-Inferiority

Two_Arm_Combined_Sample_Size

Determines the minimum sample size required for the posterior probability of a treatment effect to exceed a specified threshold, given a prior distribution and assumed effect. Supports binary, continuous, and count outcomes.

prior_mean is the mean of your prior distribution for the treatment effect—basically, what you believe the average difference between the treatment and control groups is before seeing any data. It is your best guess of the treatment effect (or the difference in means) before collecting any data. prior_sd is how uncertain you are about that guess. A larger SD means more uncertainty.

If you believe that the treatment improves the outcome by 2 units on average, and you’re fairly confident in that guess, you might use: prior_mean = 2 prior_sd = 1

If you’re not sure at all and want to stay neutral, you could use: prior_mean = 0 prior_sd = 10

{crit} is the cutoff value mentioned earlier, which is the threshold for the posterior probability of success. It is the value you want to compare against, like a benchmark or a minimum effect size. For example, if you want to be at least 90% sure that the treatment is better than the control, you would set crit = 0.9.

For example, a company wants to introduce a new productivity software and measure if it improves the average number of tasks completed per day by employees compared to the current tool. The outcome (number of tasks per day) is continuous. To determine the minimum number of employees needed in each group (new software vs. current software) to be at least 90% sure (posterior probability ≥ 0.9) that the new tool improves productivity by at least 0.2 tasks per day, assuming the expected improvement is 0.4 tasks.

Two_Arm_Combined_Sample_Size(
  type = "continuous",
  threshold = 0.2,
  crit = 0.9,
  effect_size = 0.4,
  prior_mean = 0,
  prior_sd = 1,
  sigma = 1)

Conclusion

The SSEBFF package provides a comprehensive set of tools for sample size estimation in Bayesian clinical trials. By incorporating prior information, estimating sample size, and desired posterior probabilities, it allows researchers to design trials that are statistically sound and efficient. The functions provided in this package can handle various types of outcomes, including binary, continuous, and count data, making it versatile for different clinical trial designs.
